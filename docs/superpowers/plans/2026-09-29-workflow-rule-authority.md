# 工作流规则收敛与跨阶段回归

范围：保留当前 PRD/design 取证文件设计及既有修复；不改变官方 artifact DAG，不更新业务项目。

规则归属：Soul 维护入口与全局原则；阶段文档维护阶段决策；references 维护跨阶段细则；
Skill 只编排 CLI；Schema 维护 artifact 结构与依赖；模板只保留字段和可删减示例。

验证顺序：
1. 用真实 OpenSpec 状态串联认领、协调校验、健康检查、回退及人工验收，先复现失败。
2. 修正测试暴露的人工标记识别和认领/校验不一致；失败认领不得修改记录。
3. 清除下游入口重复政策，建立必读引用和引用目标检查，保留权威文档的语义与 artifact 字段测试。
4. 全量测试、语法检查、独立审查。

风险：规则引用必须随安装完整分发；已有 change 不自动迁移；工具只能检查人工反馈存在，不能证明反馈真实性。

实现约定：认领前执行父 DAG 与可达依赖一致性门禁，包含外部父的子记录。已知兄弟记录错误也阻止
首次或幂等认领，避免 claim 成功后 validate 失败；锁内官方状态缓存仅在本次认领有效。

已复现并修复的反例：跨父依赖误报缺失、跨父环及物理名别名、父子隐含完成依赖形成的环、
外部父依赖掩盖未完成子任务、当前记录人工模式冲突、
任务内部块后的人工标记漏检。保留父子错误回退/正确恢复、无反馈与空反馈拒绝、失败认领不落盘测试。

验证完成：全量 225 项通过；最后加入隐含父子完成边的查环调整通过 26 项定向回归，
独立复核的 3 项真实 CLI 场景通过且无剩余阻断项。`npm run check` 与 `git diff --check` 通过。
规则引用测试覆盖 Skill、Schema、模板到权威文件的路径；保留官方 Schema 契约及受管安装测试。
