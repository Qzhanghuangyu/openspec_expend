# 项目 UI 组件知识库

本目录是当前项目独立维护的 UI 组件与页面模式知识库。FallaOpenSpec 只提供位置、模板和使用约束，
**不会在安装时扫描业务代码、生成组件索引或写入项目专属内容**。

## 目录约定

```text
.falla/ui-knowledge/
├── README.md                     # 本说明，由 FallaOpenSpec 管理
├── templates/                    # 通用条目模板，由 FallaOpenSpec 管理
│   ├── component.md
│   └── screen-pattern.md
├── components/                   # 项目成员或经用户明确授权的 AI 创建，一组件一文件
└── screen-patterns/              # 项目成员或经用户明确授权的 AI 创建，一页面模式一文件
```

首次记录时再创建 `components/` 或 `screen-patterns/`，不要预生成空条目、全量索引或缓存数据库。

## 维护原则

1. 每个项目只维护自己的知识库，不自动读取、合并或复制其他项目的条目。
2. 安装、更新、SessionStart 和普通任务不得自动生成知识库内容。
3. AI 只有在用户明确授权维护知识库，或当前任务明确包含知识沉淀时，才能新增或修改条目。
4. 条目必须基于当前项目中的相对路径、符号、布局或验证证据；不得把推测写成可复用事实。
5. 知识库缺少条目不等于项目没有该能力；应继续使用 CodeGraph、`rg` 和实际代码核对。
6. 复用前必须检查模块依赖、资源可见性、主题约束、API、生命周期和最近验证日期。
7. 不记录 token、cookie、密钥、签名信息、绝对用户路径、完整设计正文或临时资源 URL。
8. 组件过期时标记 `deprecated` 或 `invalid`，不要静默删除仍可能被引用的历史结论。

## 推荐命名

- 组件：`components/<stable-kebab-id>.md`
- 页面模式：`screen-patterns/<stable-kebab-id>.md`

文件名是项目内稳定标识，不使用类名哈希、绝对路径或个人姓名。

## 与 Figma 和 CodeGraph 的关系

- Figma MCP 是用户明确提供设计节点后的设计事实来源；知识库不能替代当前设计节点核对。
- CodeGraph 用于定位源码符号、调用链和影响面；知识库用于保存经过人工或任务验证的可复用结论。
- 两者结果冲突时，以当前代码、当前设计节点和实际验证为准，并更新或降级知识库条目状态。
