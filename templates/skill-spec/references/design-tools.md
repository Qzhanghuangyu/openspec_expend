# 设计源与 Figma MCP

## 何时读取

依赖设计事实、设计节点或工程素材时读取；代码组件选型见 `ui-knowledge.md`。

## 授权与访问边界

- 首次授权须由用户在当前对话提供带 node id、用于当前 change 的 Figma 链接；不跟随 PRD 链接。
  缺少 node id 时请用户重新选择。已记录的授权仅覆盖原 change 和精确节点，不要求用户重复粘贴同一链接。
- 新节点、用途、变量、组件关系或资源元数据超出已确认范围，先请用户确认；授权记录不明确时也须确认。
  不自行读取整个文件、相邻节点或响应中附带的未授权祖先/依赖。此边界同样适用于补读、导出与异常诊断。
- 默认通过 Figma MCP 读取，不得使用浏览器、WebFetch、`curl` 或 DOM 抓取降级；REST 例外见下文。
  其他设计平台优先使用专用 MCP 或语义连接器；普通网页参考不受此限制。
- `get_design_context` 显式传 `excludeScreenshot=true`；默认不调用 `get_screenshot`，不向模型发送
  页面视觉复现截图、截图 URL 或图片块。只有下文的资源异常诊断允许截图。
- 保密底线遵循 Soul；file key/node id 只记当前 change 必需范围，不复制到公开材料。
  认证信息、cookie、token 和临时资源 URL 不得硬编码进命令或泄露到输出、日志、artifact、handoff、仓库或回复。

## 文件职责与跨阶段复用

按 Schema 模板在父 change 建立取证文件；子 change 读取父文件，不另存副本。
只读取项目内普通文件，不跟随符号链接或越界路径，不保存原始链接、完整节点正文或截图。

| 文件 | 保存内容 |
| --- | --- |
| `design-source.md` | 授权范围/日期、设计条目 ID 到 file key/精确 node id 的映射、取证状态、已取得事实与缺口、工程资源来源、倍率、尺寸、相对路径及本地哈希 |
| `preflight.md` | 人工可读的授权概要与分析缺口 |
| `design.md` | 设计生成后的实施事实、关键节点文本规格、资源齐备结论与未决项 |

- design 未生成时从取证文件交接事实；生成后以 design 为实施依据，访问节点或使用资源时再读取证台账。
  旧 change 的既有授权与技术引用可迁入 `design-source.md`，迁移不扩大授权、不触发重读，安装器不改写已有人工文档。
- 已核对事实足够时直接复用；本地资源存在且哈希吻合时可直接复用。哈希只证明文件未变，不证明视觉一致。
- 缺少必要结构、状态、元数据或资源二进制时，先列缺口，只补读已授权的精确节点；用户告知设计变化或
  要求最新设计时也须核对。阶段切换、新会话、开始 UI task 或核对日期较早本身不构成重读条件；日期不能证明远端未变。
- 缺失实施必需事实或资源且无法补齐时，暂停受影响任务并记录恢复条件；MCP 不可用、未认证、无权限或
  节点失效时同样处理，不推测缺失值。重读有差异时由 Propose 更新 design；Apply 暂停当前任务并返回 Propose。

## 设计事实提取

只提取当前页面/状态主要区域必要的父子关系、节点标识、尺寸/约束/间距及单位、文案、字体/颜色变量、
效果参数、状态和资源引用。为区域分配稳定的设计条目 ID，在 `design-source.md` 映射已授权精确节点，
在 design 的“关键节点文本规格”映射 Android 目标节点；不把 file key/node id 复制进 design/tasks。
实施必需事实或资源缺失时标“待澄清”并暂停受影响任务；结构化数据无法判定的观感标“人工视觉校准”，
注明区域与验收条件，不以人工校准代替必需事实。未经核实不把 Figma 数值直接当成 Android dp，
不抄完整节点树或推断栅格素材外观。运行时核对与人工视觉验收见 `android-quality.md`。

- 若源码已证实当前页面使用 AutoSizeConfig 按宽适配，`design_width_in_dp` 等于设计稿的 1× 逻辑画布宽，
  且该页没有取消适配或改用按高/自定义基准，尺寸与间距可按同数值 dp 落地；例如双方宽度均为 375 时，设计间距 16 对应 16dp。
  这不代表物理像素，也不自动涵盖文字的 sp、字体缩放或位图资源。design 记录配置位置、模式、画布单位及页面例外；未证实则保留原单位。
- 设计稿高度（如 812）是参考画布，不用它修改 `design_height_in_dp`（如 667）或按高度比例压缩页面。
  按宽适配下该配置不决定实际内容高度；记录设计是否包含系统栏，实际可用高度与 Insets 留待运行时核对。

## 工程资源交付

看图（理解设计）与用图（交付资源）是两条管线。截图/预览不能作为切图交付；禁止截图放大、裁剪合成、
Alpha 蒙版恢复或按颜色抠图补救。所有资源均遵守上文授权边界和文件台账约定。

1. **选择来源**：先复用符合设计、尺寸与效果的正式资源/成品。`download_assets` 的 `rawImages` 是原始图片，`export` 是节点渲染结果；
   原图缺少节点裁剪、滤镜等效果时，须取正确节点的原生 Export 或设计师成品；未经核对等价的 `rawImages` 不得下载并冒充节点工程切图。
   个别节点的导出可能将预期透明区域压成背景色，不能只看 PNG 格式或 Alpha 通道存在就认定结果合格。
2. **原生导出**：仅对已授权的精确节点执行原生 Export，优先沿用设计节点已有的导出格式与倍率；
   只有用户明确要求 3x PNG 时，才在 `download_assets` 中覆盖节点设置，显式指定 `png` 和 `scale=3`；`scale=3` 对应 xxhdpi。
   透明切图不用 `jpg`。需要 `svg` 时另核对 Android 交付方式，不强制把矢量栅格化。
   如当前授权的是页面/Frame，但工程切图须从子节点导出，先列出必要的子节点并取得范围确认，不导出整页或自动遍历无关图层。
3. **下载与验收**：临时资源 URL 仅可通过批准的二进制下载方式取得对应文件，不用于读取新节点。
   下载到临时位置，核对文件格式，并将设计逻辑尺寸与实际像素逐项比对：请求 3x 时核验 3x 倍率，否则核对节点原有倍率；失败不留下半成品。
   新导出且预期透明的 PNG，可先用 `sips -g hasAlpha <file>` 核验 `hasAlpha: yes`（macOS）；还须确认确有像素的 Alpha < 255，
   不能仅凭通道存在放行。若已安装 Pillow，可读取 `Image.open(file).convert('RGBA').getchannel('A').getextrema()[0]`，
   最小值必须小于 255；工具不可用时换用可信的图像检查方式，不能推测透明。黑白底或不透明异常均不得交付。
   已在项目中正式交付的资源不强制新增 Alpha、边角、Frame Fill 或隔离渲染检查；不透明照片/背景和 SVG 也不适用透明检查。
4. **登记与交付**：验收通过后在 `design-source.md` 的工程资源台账记来源类型、请求倍率、设计逻辑尺寸、实际像素、
   项目内路径及本地哈希，不记录 token、临时 URL 或原始 API 响应；哈希证明未变，不代替视觉验收。
   未获授权、无法安全下载或验收失败时，保留资源 task 未完成并写明恢复条件。

### 异常与例外

- **具体资源异常**：仅在用户反馈、实际页面出现黑白底/不透明异常，或透明 PNG 验收失败时，核对目标节点的
  可见 Fill、Frame 底色和导出设置（如 Show in exports）；可调用 `get_screenshot(contentsOnly=true)` 辅助诊断。
  诊断截图不入库、不写交接或回复。无法取得正确原图/切图时，请设计师提供透明 3x 原件，按项目规则使用明确占位并标记待人工替换。
- **受限 REST**：MCP 无原生导出能力时，须先取得用户对当前精确节点的 REST 降级授权；原生导出不通过透明度验收时也不能自行绕过授权。
  授权后只可请求图像导出端点 `GET https://api.figma.com/v1/images/:fileKey?ids=:nodeId&format=png&scale=3`（此处 3x PNG 仅为已确认交付规格的示例）；
  `ids` 只填当前获准的精确节点，将 Web node id 的 `-` 转为 `:` 并 URL 编码，不借降级请求文件 JSON 或扩展节点范围。
  核对 HTTP 状态、响应的 `err` 以及 `images[nodeId]` 是否有效；返回的临时图片 URL 仅用于下载对应二进制，下载请求不携带 Figma 认证头。
  token 不从 Shell 启动文件自动探测，不在命令参数、输出、日志或 artifact 中暴露凭据、原始 JSON 与临时 URL。
  失败则暂停并说明脱敏原因，不把诊断截图、放大的原图或未经验证的导出当工程资源。

### 可选 WebP 优化

在已验收的正式位图上，且项目的 `minSdk` 和目标设备支持时，才可使用 `cwebp -q 85 <input.png> -o <output.webp>`
尝试减少包体积。点九图 `.9.png` 不转换；作为 `res/drawable*` 资源交付的 WebP 至少核对 Android API 17，
透明或无损 WebP 则要求 API 18 及以上。若业务仍支持更低版本设备，不得只替换原 PNG，须提供可用的 PNG 回退资源。
精细半透明图标应评估无损编码，转换后逐项检查尺寸、透明度、视觉效果与实际文件大小；
仅在效果合格且有收益时替换原 PNG，更新资源引用与台账哈希，避免同时打包重复文件。
`--with-webp` 只准备工具，不自动改动业务资源。
