# 设计源与 Figma MCP

## 何时读取

当前阶段需要读取或继续依赖设计稿节点时读取。没有设计稿任务时不要加载。

## 规则

- 首次授权节点时，用户必须在当时的对话中另行提供包含 node id、明确用于当前 change 的 Figma 链接。
  不读取或自动跟随 PRD 正文中的设计稿链接；缺少 node id 时请求用户重新选择。
- 收到明确授权后先保存稳定引用，不等 Figma 分析结束才落盘：Preflight 写入 `preflight.md` 的
  “设计节点交接”；Propose 若尚不能写 design，也先将新节点追加到该节。只记录确认日期、当前 change
  与节点范围、file key、精确 node id 和脱敏状态，不保存原始链接、查询参数或整段对话。
- Propose 从 preflight 交接节点，并在 `design.md` 的“设计源证据”记录授权范围、节点最后核对日期、
  实施所需事实、资源的项目内相对路径与下载状态/本地文件哈希、未决项和重新核对条件。
  design 可写后以该节为唯一设计事实源；preflight 仅保留授权来历，不维护第二份资源台账。
- 新会话在设计尚未成稿时读 preflight 交接；design 已生成后只以父 design 为设计事实源。
  已记录的授权仅覆盖原 change 和精确节点，
  不能用来读取其他节点或整个文件，也不要求用户重复粘贴同一链接。已有事实足够且本地资源存在、
  哈希吻合时可直接复用；本地资源须是项目内普通文件，不跟随符号链接或越界路径。
  缺失二进制或必要元数据、用户告知设计变化、或明确要求按最新设计实施时，
  只重新读取已授权节点。
  新节点、用途/范围扩大或授权记录不明确时必须请用户确认；无法凭核对日期推断远端设计未变化。
- 看图（理解设计）与用图（交付资源）是两条管线，不得把截图或预览当作工程切图。
  默认只通过 Figma MCP 读取节点，不得使用浏览器、WebFetch、`curl`、网页截图或 DOM 抓取降级；
  仅在 MCP 无法原生导出且用户另行授权时，才按下述受限 REST 例外处理。
- 看图只用于理解布局、层级与视觉关系，结果不落地为工程资源。`get_design_context` 必须显式传
  `excludeScreenshot=true`；默认不调用 `get_screenshot`，不得为页面视觉复现向模型发送截图、截图 URL
  或图片块。仅已有具体黑白底/不透明异常时，才按下述诊断例外处理，不得把诊断截图用于交付。
- 先读取指定 node；相邻节点、变量、组件关系和资源元数据若超出已确认范围，先请用户确认，
  不自行选择整个文件。
- 从已授权节点的文本/结构化结果中，只提取当前页面的根容器、关键内容和需验收状态：父子关系、
  节点标识、尺寸与约束、主要间距、可见文案、字体/颜色变量、组件状态和资源引用。只记工具实际
  返回且实施必需的值和单位，不逐控件抄写完整设计；缺少值写“未取得”，未经核实不把 Figma
  数值直接当成 Android dp，也不推断栅格素材内容。目标 Android 节点标识及可观察状态写入 design 的
  “关键节点文本规格”，供 Apply 对照；无法确定的视觉细节留给人工校准，不得猜测。
- 若项目源码已证实当前页面使用 AutoSizeConfig 按宽适配、`design_width_in_dp` 与设计稿的 1×
  逻辑画布宽度相同，且该页没有取消适配或改用按高/自定义基准，可在该适配坐标系中将设计尺寸、
  间距的数值按 1:1 落为 dp；例如双方宽度均为 375 时，设计间距 16 对应 16dp，不代表设备
  物理像素，也不自动涵盖文字的 sp、字体缩放或位图资源。把配置位置、适配模式、画布宽度/单位
  和页面例外核对证据写入 design；条件未证实时继续保留原单位和待确认项。
- 设计稿高度（如 812）是参考画布，不用它修改 `design_height_in_dp`（如 667）或按高度比例
  压缩页面；按宽适配下该高度配置不决定当前页面的缩放和实际可用高度。记录画布是否包含系统栏
  等设计边界，实际内容高度与 Insets 留待运行时核对，不用画布高度减配置高度推断溢出量。
- 已授权范围内的变量、素材只记录与关键节点有关的名称、值或项目内路径；读取其他节点或扩大
  用途仍须用户确认。资源文件哈希证明文件未变，不证明图标或页面视觉一致。
- MCP 未安装、未认证、无权限、节点失效或返回不完整时，停止依赖该设计的工作并报告恢复条件；
  重新认证不等于重新索要已记录的节点引用。重读发现差异时，Propose 更新 design；
  Apply 暂停当前任务并返回 Propose，不自行扩大方案。
- 临时资源 URL、认证信息、cookie、token 和完整设计正文不得写入日志、artifact 或 handoff。
  file key 与 node id 也只写当前 change 所需的最小范围，不复制到不受控的公开材料。
- 其他设计平台同样优先使用专用 MCP 或语义连接器；普通网页参考不受此限制。

## 用图：工程资源取得与验收

1. 先核对项目已有正式资源或设计源提供的原图/正式切图；已符合设计、尺寸和所需效果的成品直接复用。
   `download_assets` 的 `rawImages` 是原始图片，`export` 是节点渲染结果，不能混用。原图不包含节点
   裁剪、滤镜等最终效果时，只取正确节点的原生导出，或请设计师提供正式成品，不把原图冒充最终切图。
2. 新切图只针对已授权范围内的精确节点走原生 Export，不能使用 `get_screenshot`、页面截图、截图
   放大或裁剪合成。导出时显式指定 `png` 或 `svg`，不得用无 Alpha 通道的 `jpg` 承载透明切图；
   Android 位图通常用 `scale=3` 对应 xxhdpi，仅像素比对场景用 `scale=2`。确认目标节点、格式、
   倍率与项目资源目录后再落盘；SVG 须确认 Android 可使用的交付方式，不用 PNG 的 `sips` 命令
   验收 SVG；背景异常按第 4 项诊断。
3. 需要透明的新导出 PNG 必须在入库前用 macOS `sips -g hasAlpha <file>` 核验为 `hasAlpha: yes`；
   `no` 立即失败，不交付。`yes` 只证明存在通道，若仍可见黑白底或像素不透明也不得交付。
   本来就不透明的照片/背景、SVG，以及直接复用的已有正式资源/成品原图不强制新增 Alpha、边角、
   Frame Fill 或隔离渲染检查；按现有台账记录项目内路径与哈希即可。
4. 用户反馈或实际页面出现黑白底等具体异常，或新导出透明 PNG 的 Alpha 验收失败时，只核对
   已授权精确节点的可见 Fill、Frame 底色和导出设置（如 Show in exports）。此时可对该节点调用
   `get_screenshot(contentsOnly=true)` 辅助诊断；截图及临时 URL 不入库、不写入交接或回复，不能当
   最终切图。追溯父节点或改取矢量子节点若超出授权范围，先请用户确认；获授权后对正确子节点
   原生导出。禁止截图放大、裁剪合成、Alpha 蒙版恢复、按颜色抠图等二次加工补救。若没有无需加工
   的正确原图/节点切图，请设计师提供透明 3x 原件，按项目规则使用明确占位并标记待人工替换。
5. MCP 返回的临时资源 URL 仅可通过批准的二进制下载方式保存对应的原图/导出文件，不用于读取
   新节点，不写入日志、artifact、handoff、仓库或回复；交付后只按 design 台账保留必要的项目内
   路径和哈希，不记录取得方式、倍率或逐项验收过程。无法安全下载或验收时停止交付，不改用截图。
6. MCP 无原生导出能力时，须先取得用户对当前节点的 REST 降级授权，才能用带 `X-Figma-Token`
   的 Figma REST GET 读取指定 node 和所需原生导出；Web 链接中的 node id `-` 转为 API 的 `:`。
   响应即使包含祖先或依赖，也不得利用/记录超出确认范围的内容；相邻节点、变量、组件关系及
   资源元数据超出范围时先确认。不得在命令、日志或文档中泄露 token 或临时 URL，失败则暂停。
