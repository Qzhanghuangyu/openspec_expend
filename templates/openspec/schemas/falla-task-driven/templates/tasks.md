# 子任务

- 粒度：每项任务应能在一次独立实施上下文内完成定位、修改、验证和交接；跨度过大时返回父 change 拆分。
- 描述：每项任务写明必要输入、允许编辑范围、完成条件和前置依赖，以便压缩或换会话后恢复。
- 范围：只包含当前子 change 必需改动；知识库、lint、测试或代码检索发现的无关问题只记录，不自动整改。

## 验证模式

- 模式：hybrid
- 说明：默认由 Agent 执行 formatter、lint、单元测试、编译和可自动化静态检查，由人工执行真机、真实服务端联调和视觉验收；只有用户明确要求时才能改为 human 或 agent。
- 人工任务：带 `[人工]` 的 checkbox 只能依据人工明确反馈勾选，Agent 不自行执行或推定通过。

## 1. 结构与边界复核

- [ ] 1.1 核对父 design 的页面实现结构基线、required 实现基线、当前子 change 边界及前置依赖；如存在项目规则目录，读取其顶层普通 `.md` 文件并核对当前子 change 命中的规则；涉及页面时，根页面/XML 只能由指定责任方修改（依赖：按父 change DAG）

## 2. 实施

- [ ] 2.1 按已确认的结构和边界完成当前子 change 的最小实现（依赖：1.1）

## 3. 验证与交接

- [ ] 3.1 覆盖空值、异常、弱网和重复操作（依赖：2.1）
- [ ] 3.2 验证协程、Flow、观察者、回调和监听器按生命周期取消或释放，且页面销毁后不再更新 UI（依赖：2.1）
- [ ] 3.3 检查日志、缓存、网络请求和产物不包含凭据或未脱敏的敏感信息（依赖：2.1）
- [ ] 3.4 检查触及的 Android XML 已按属性逐行、层级缩进的纵向格式排版，且没有无关格式化（依赖：2.1）
- [ ] 3.5 检查新增或实质修改的类、方法和参数已有职责说明；公共/受保护方法使用 KDoc/JavaDoc，参数说明业务含义、单位/范围、可空性、所有权或回调时机，必要时说明返回值、异常、线程和生命周期约束，且注释不含敏感正文（依赖：2.1）
- [ ] 3.6 已知继承声明、组件、资源和数据更新 API 时使用有界 `rg` 精确检查；需要真实调用方、间接实现或影响面时使用 CodeGraph，确认结果与父 design 的 required 基线一致；任何偏离先返回 propose，不以 lint 或局部优化理由替代（依赖：2.1）
- [ ] 3.7 检查实际 diff 符合父 design 绑定的 required 项目规则，并将 Rule ID 与证据写入 handoff；偏离时返回 propose 记录例外（依赖：2.1）
- [ ] 3.8 检查 diff 仅包含当前子 change 必需改动；无顺带重构、资源迁移、依赖升级、无关格式化或既有告警修复（依赖：2.1）
- [ ] 3.9 记录 formatter、lint、资源编译等验证命令、variant/设备、结果和未通过项；不适用项写明原因（依赖：3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8）

- [ ] 3.10 [人工] 按验收清单在目标 variant/设备执行当前子 change 的核心交互、边界状态和真实服务端联调，并记录逐项结果（依赖：3.9）
- [ ] 3.11 [人工] 完成当前子 change 的视觉、动效、字体、间距和机型适配校准，并记录可接受偏差（依赖：3.10）
