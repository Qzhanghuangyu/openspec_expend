# 任务

## 执行模式

- 模式：single
- 说明：默认由父 change 直接实施；只有用户明确要求并行分派时才改为 parallel 并创建子 change。
- 粒度：每项任务应能在一次独立实施上下文内完成定位、修改、验证和交接；跨度过大时继续拆 task。
- 描述：每项任务写明必要输入、允许编辑范围、完成条件和前置依赖，以便压缩或换会话后恢复。

## 1. 页面实现结构基线

- [ ] 1.1 复核 design 中的页面承载方式、文件归属、复用边界及 XML / Compose 节点结构与当前项目一致；不适用或不一致时写明原因（依赖：无）
- [ ] 1.2 涉及新建或重构页面时，按结构基线创建最小可编译页面骨架，验证根布局、导航入口、状态容器、Insets 和 ViewModel 作用域；非页面变更写明不适用原因（依赖：1.1）

## 2. 契约与 ViewModel

- [ ] 2.1 定义可验证的数据、状态、事件与副作用契约（依赖：1.2）

## 3. UI 模块控件

- [ ] 3.1 搭建独立控件框架（依赖：1.2, 2.1）

## 4. 组装与验证

- [ ] 4.1 按已确认的页面结构组装页面并执行功能验证（依赖：3.1）
- [ ] 4.2 覆盖空值、异常、弱网和重复操作（依赖：4.1）
- [ ] 4.3 验证协程、Flow、观察者、回调和监听器按生命周期取消或释放，且页面销毁后不再更新 UI（依赖：4.1）
- [ ] 4.4 检查日志、缓存、网络请求和产物不包含凭据或未脱敏的敏感信息（依赖：4.1）
- [ ] 4.5 检查触及的 Android XML 已按属性逐行、层级缩进的纵向格式排版，且没有无关格式化（依赖：4.1）
- [ ] 4.6 检查新增或实质修改的类、方法和参数已有职责说明；公共/受保护方法使用 KDoc/JavaDoc，参数说明业务含义、单位/范围、可空性、所有权或回调时机，必要时说明返回值、异常、线程和生命周期约束，且注释不含敏感正文（依赖：4.1）
- [ ] 4.7 记录 formatter、lint、资源编译等验证命令、variant/设备、结果和未通过项；不适用项写明原因（依赖：4.2, 4.3, 4.4, 4.5, 4.6）
- [ ] 4.8 记录需要人工校准的视觉项（依赖：4.1）
